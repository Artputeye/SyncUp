## Implemented

1. `ModuleManifest` now declares supported `workspaceTypes`; the current `commerce` manifest is POS-only.
2. Added code-backed Provisioning Profiles:
   - `pos-standard@1.0.0`: allows `commerce`, declares `commerce` as a default module.
   - `online-standard@1.0.0`: no modules allowed/defaulted yet; Online modules are not implemented.
3. Added authenticated read-only `GET /api/workspaces/:workspaceId/modules/profile` endpoint for the effective profile.
4. Module compatibility responses include Workspace Type and Profile ID and reject modules outside either the profile allowlist or manifest type support.
5. Install and Enable enforce compatibility server-side.
6. Disable remains available for cleanup if a module is no longer compatible with the Workspace's current profile.
7. Untyped legacy Workspaces fail closed for compatibility, profile resolution and Install; no type is inferred or backfilled.
8. Extended the disposable module lifecycle integration test to verify POS allow, ONLINE deny, untyped deny, Enable denial, Disable cleanup, and existing RBAC/Audit behavior.

- Declared default modules are metadata only; automatic module installation is not executed in this milestone.
- Online Profile intentionally has an empty allowlist until Online domain modules are implemented.
- Current `commerce` is a broad POS-oriented module. Splitting Online Catalog/Storefront/Checkout/Orders into separate Online modules is future Online-track work.
