## 1. Branch / Warehouse lifecycle implementation

Added `apps/api/src/core/tenant/store-lifecycle.service.ts` and routes in `tenant.controller.ts`:

- Store creation inserts Store + default Branch + default Warehouse in one Tenant DB transaction.
- Branch creation inserts its default Warehouse in the same transaction.
- Warehouse creation locks its Branch row; Store/Branch default operations lock the parent row with `SELECT ... FOR UPDATE`.
- Default replacement, archive state changes and `AuditLog` inserts run in one transaction.
- A Branch cannot lose its last active Warehouse; a Store cannot lose its last active Branch.
- Archiving a default Branch/Warehouse selects a replacement default in the same transaction. Branch archive also archives its Warehouses and is rejected while stock balances are non-zero.
- New permission `commerce.store.manage` is assigned to the workspace admin role for existing workspaces by Control DB migration `202611030001_commerce_store_manage`; new Workspace role bootstrap includes it. Owner remains authorized by the existing RBAC owner bypass.

Database enforcement candidate:
- `tenant-branch-warehouse-lifecycle.candidate.sql` adds deferred constraint triggers enforcing exactly one active default Branch per active Store and at least one active Warehouse plus exactly one active default Warehouse per active Branch.
- Existing partial unique indexes remain the immediate at-most-one-default guard.
